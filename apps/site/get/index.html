Get ClaimTrace

Three ways to run the same engine. Pick by where your documents may go.

  1. In the browser For anyone. No install, no account. Needs A current desktop browser Documents Stay in the tab
  2. With Claude A skill for Claude.ai, or a plugin for Claude Code. Needs A Claude plan with skills and code execution, or Claude Code Documents Go to Anthropic
  3. Self-host The full app on your own machine or server. Needs Docker, or Python 3.11+ and Node 20+ Documents Stay on your machine

In the browser

The real engine runs inside the browser tab, with no account and nothing to install.

What it needs
A current desktop browser: Chrome, Edge, Firefox or Safari. The first visit downloads about 18 MB.
Where your documents go
Nowhere. Your file is read inside the tab and never uploaded. Close the tab and it is gone.

  1. Open the try page in a current desktop browser. The first visit downloads the engine, so give it a moment.

  2. Load the sample documents, or choose your own contract, amendment or report.

  3. Read who owes what, ask a question, or check one document against another.

The browser version uses the rules engine only: no language model, and no OCR for scanned PDFs.

Try it in your browser

Nothing is uploaded.

With Claude

Claude runs the engine for you on documents you attach, and answers with its quotes. Two ways in: a skill for Claude.ai, or a plugin for Claude Code.

What it needs
Claude.ai: a plan with skills and code execution; a work or school account may need an administrator to allow them. Claude Code: the plugin, and Python 3.11 or newer.
Where your documents go
To Anthropic. Do not use this path for documents you may not share with Anthropic.

On Claude.ai, as a skill

  1. Download claimtrace-skill.zip from the latest release. Do not unzip it.

  2. In Claude.ai’s settings, turn on code execution, then upload claimtrace-skill.zip as a skill and make sure it is switched on. The exact menu names can change; look for the skills and code execution settings.

  3. Start a new chat, attach the contract and its amendments or reports in the same message, and ask, for example:

    Use ClaimTrace to check whether the amendment changed the delivery date in the contract.

The first time in a chat, Claude reminds you that attached documents are processed by Anthropic. Answers quote the documents word for word with section numbers. Amendment results need your check: on wording it had not seen before, the engine’s amendment verdicts were right 0.60 of the time.

Where your documents go
To Anthropic. The files you attach, and the results, are processed by Claude under your plan’s terms, as in any chat. The engine runs in Claude’s code sandbox. Do not use this path for documents you may not share with Anthropic.

Using ClaimTrace with Claude, in full

In Claude Code, as a plugin

  1. In Claude Code, add the marketplace:

    /plugin marketplace add glowstonesq1/claimtrace

  2. Install the plugin, and restart Claude Code if it asks:

    /plugin install claimtrace@claimtrace

  3. Check a folder, or ask one question:

    /claimtrace:claimtrace-check ./contracts
/claimtrace:claimtrace-ask "Did the amendment change the delivery date?" ./contracts

The plugin uses ClaimTrace if it is already installed. If not, Claude asks you once before installing ClaimTrace v0.3.0 from GitHub into a private folder for the plugin (about 50 MB, needs network), and installs nothing unless you agree. Claude Code also asks permission before it runs the install.

Or skip the GitHub install: unzip claimtrace-plugin.zip and start Claude Code with claude --plugin-dir pointing at that folder. The zip contains the plugin, the ClaimTrace engine and its pure-Python dependencies (pypdf, python-docx, defusedxml). It does not contain the compiled packages, which must already be installed for your python3 (3.11 or newer): pydantic 2 with pydantic_core, and lxml for .docx files. If one is missing, the plugin stops with exit code 3 and a message naming the package and the pip install command; Claude shows you that and installs nothing on its own. If you would rather not install them yourself, ask Claude to run the plugin’s install --yes, which puts ClaimTrace and everything it needs in a private folder, as above.

Where your documents go
The engine runs on your computer and the files stay on your disk. The quotes and results it prints, and any file Claude opens, go into the conversation and so to Anthropic, under your Claude plan or API terms.

Plugin details and commands

Self-host

The full app, with its web interface and command line, on your own machine or a server your IT team runs.

What it needs
Docker with Compose, or Python 3.11+ and Node 20+. Git to get the code.
Where your documents go
Nowhere else. Nothing leaves your machine by default, and a test enforces it.

With Docker Compose

One Compose file. It serves on 127.0.0.1:8000 only, as a non-root user with a read-only filesystem.

  1. Get the code and start it:

    git clone https://github.com/glowstonesq1/claimtrace
cd claimtrace
docker compose up --build

  2. Open http://127.0.0.1:8000 and click Load sample documents.

  3. Before you expose it beyond this host, read the security model. It refuses to listen on another address without CLAIMTRACE_API_TOKEN set.

Where your documents go
Into the claimtrace-data volume on that host, and nowhere else by default.

Security model, for your IT team

From source, in a terminal

  1. Get the code and set it up:

    git clone https://github.com/glowstonesq1/claimtrace
cd claimtrace
make dev

  2. Start it, then open http://127.0.0.1:8000 and click Load sample documents:

    make serve

  3. Or use the command line. It reads PDF, DOCX, Markdown and plain text:

    .venv/bin/claimtrace ingest examples/documents/msa-v1.md
.venv/bin/claimtrace ingest examples/documents/amendment-1.md
.venv/bin/claimtrace ask "How many days does the customer have to pay invoices?"
Where your documents go
Nowhere. Nothing leaves your machine by default, and a test enforces it. A hosted model, if you add one, sees only documents you approve.
